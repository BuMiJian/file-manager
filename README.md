# file-manager

按资料类型和调研日期给文件统一编号重命名，并把编号写入 SQLite 台账（`data.db`）。

## 命名规则

```
{类型}{YYMMDD}-{序号:04d}-{原文件名}
```

例如：`ZL251017-0001-生产运行报告.pdf`

- **类型**：`ZL`、`SP`、`JY`、`SW` 之一，默认 `ZL`
- **日期**：从文件所在目录往上找，取最近一个以 `YYMMDD-` 开头的目录名，按 20YY 年解析
- **序号**：在同一类型、同一日期内从 1 递增，接着台账中已有的最大序号往下编

## 用法

只依赖 Python 标准库，无需安装依赖。

```bash
# 使用默认资料目录
python3 file-manager.py

# 指定目录和类型
python3 file-manager.py ~/某个资料目录 --type SP
```

运行结束会输出重命名和跳过的文件数量。

## 处理逻辑

1. 递归扫描目录下的文件，跳过隐藏路径、符号链接和 `.db` 文件。
2. 先把已经符合命名规则的文件登记到台账，避免新文件占用旧编号；编号和台账不一致时报错退出。
3. 再给未编号的文件生成新名称、写入台账并重命名。找不到有效日期的文件会跳过。
4. 中途出错时，数据库回滚，已重命名的文件也会改回原名。

## 文件说明

| 文件 | 说明 |
|---|---|
| `file-manager.py` | 主程序 |
| `revoke.py` | 早期的撤销脚本，与当前命名规则不匹配，暂不建议使用 |
| `data.db` | 台账数据库，运行时在当前工作目录生成，不纳入 git |
| `web/` | 可视化页面（预留，尚未实现） |

## 注意事项

- `data.db` 按**当前工作目录**创建，请始终在项目根目录下运行，否则会生成新的空台账，导致编号重复。
- 程序会直接重命名真实文件，首次对新目录运行前建议先备份。
